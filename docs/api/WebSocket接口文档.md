# WebSocket 接口文档

本文档描述了 `Medlink` 平台提供的 WebSocket 接口，用于实时订阅设备数据。

---

## 1. 连接流程

### 1.1. 连接地址

- **URL**: `ws://<host>:<port>/medlink/device-data-ws`
- **协议**: `WebSocket`

### 1.2. 认证机制

WebSocket 连接采用基于URL查询参数的签名认证机制，以确保连接的安全性。

#### 1.2.1. 认证参数

连接时，需要在URL中附加以下查询参数：

| 参数          | 类型     | 必填 | 描述                                   |
| ------------- | -------- | ---- | -------------------------------------- |
| `X-App-Id`    | `String` | 是   | 开放平台分配的应用ID。                 |
| `X-App-Key`   | `String` | 是   | 开放平台分配的应用Key。                |
| `X-Timestamp` | `Long`   | 是   | 当前的Unix时间戳（秒）。               |
| `X-Nonce`     | `String` | 是   | 随机字符串，用于防止重放攻击。         |
| `X-Signature` | `String` | 是   | HMAC-SHA256 签名，详见下文。           |

#### 1.2.2. 签名算法

签名通过 `HMAC-SHA256` 算法生成，密钥为应用的 `App Secret`。

**步骤:**

1.  **拼接签名字符串 (`stringToSign`)**:  
    将 `App Key`、`Timestamp`、`Nonce` 和 `Request Path` 按顺序拼接。
    ```
    stringToSign = appKey + timestamp + nonce + requestPath
    ```
    - `requestPath` 是指WebSocket URL的路径部分，例如：`/medlink/device-data-ws`。

2.  **计算签名**:  
    使用应用的 `App Secret` 作为密钥，对 `stringToSign` 进行 `HMAC-SHA256` 计算，并输出为十六进制（Hex）字符串。

**伪代码示例:**

```javascript
const appKey = "your_app_key";
const appSecret = "your_app_secret";
const timestamp = Math.floor(Date.now() / 1000);
const nonce = "random_string_here"; // e.g., generated by a function
const requestPath = "/medlink/device-data-ws";

const stringToSign = `${appKey}${timestamp}${nonce}${requestPath}`;

// 使用 crypto-js 库示例
const signature = CryptoJS.HmacSHA256(stringToSign, appSecret).toString(CryptoJS.enc.Hex);
```

#### 1.2.3. 完整连接URL示例

```
ws://localhost:8848/medlink/device-data-ws?X-App-Id=...&X-App-Key=...&X-Timestamp=...&X-Nonce=...&X-Signature=...
```

## 2. 消息格式

连接建立后，客户端和服务端通过指定的格式进行通信。

### 2.1. 客户端 -> 服务端 (订阅消息)

客户端通过发送JSON格式的文本消息来订阅或取消订阅指定设备的实时数据。

**消息结构:**

| 字段        | 类型           | 必填 | 描述                                                         |
| ----------- | -------------- | ---- | ------------------------------------------------------------ |
| `type`      | `String`       | 是   | 操作类型。`subscribe` 表示订阅，`unsubscribe` 表示取消订阅。 |
| `deviceIds` | `Array[String]` | 是   | 要操作的设备ID列表。                                         |
| `overwrite` | `Boolean`      | 否   | **仅对`subscribe`有效**。`true`表示覆盖当前所有订阅，`false`或不传表示在现有订阅基础上新增。 |

**订阅示例:**

```json
{
  "type": "subscribe",
  "deviceIds": ["device_id_1", "device_id_2"],
  "overwrite": false
}
```

**取消订阅示例:**

```json
{
  "type": "unsubscribe",
  "deviceIds": ["device_id_1"]
}
```

### 2.2. 服务端 -> 客户端 (设备数据)

订阅成功后，服务端会以**二进制**格式向客户端推送设备数据。数据使用 `Protobuf` 进行序列化。

#### Protobuf 定义 (`DeviceMessage.proto`)

为了解析收到的二进制数据，需要使用以下 `.proto` 文件定义。

```protobuf
syntax = "proto3";

package org.jetlinks.community.network.websocket.protocol;

option java_outer_classname = "DeviceMessageProto";

// 顶层设备数据结构
message DeviceData {
    string device_id = 1;     // 设备ID
    int32 data_type = 2;      // 数据类型 (0: 属性, 1: 波形)
    repeated ContentItem content = 3; // 数据内容项列表
    int64 time = 4;           // 消息时间戳 (毫秒)
}

// 数据内容项
message ContentItem {
    string category = 1;      // 数据分类 (通常是属性ID或功能ID)
    ResultValue result = 2;   // 结果值
    string unit = 3;          // 单位 (暂未使用)
    string alarm_value = 4;   // 告警值 (暂未使用)
    int64 take_time = 5;      // 采集时间戳 (毫秒)
    int32 sampling_rate = 6;  // 采样率 (仅对波形数据有效)
}

// 结果值 (使用 oneof 确保只有一个字段有值)
message ResultValue {
    oneof value {
        string string_value = 1;    // 字符串类型的值
        Waveform waveform_value = 2;// 波形数据
        double double_value = 3;    // 浮点数值
        bool bool_value = 4;        // 布尔值
    }
}

// 波形数据
message Waveform {
    repeated int32 values = 1; // 波形数据点集合
}
```

## 3. 完整对接流程示例

1.  **准备认证信息**: 获取 `App ID`, `App Key`, `App Secret`。
2.  **构建连接URL**: 按照 `1.2` 中的描述，生成 `timestamp`, `nonce`，计算 `signature`，并拼接成完整的WebSocket URL。
3.  **建立连接**: 使用标准的WebSocket客户端连接到上述URL。
4.  **发送订阅请求**: 连接成功后，发送 `2.1` 中定义的 `subscribe` JSON消息，订阅感兴趣的设备。
5.  **接收并解码数据**: 监听WebSocket的 `onmessage` 事件。收到二进制数据后，使用 `DeviceMessage.proto` 的定义进行解码，得到 `DeviceData` 对象。
6.  **业务处理**: 根据解码后的数据进行业务处理。
7.  **取消订阅 (可选)**: 如果不再需要某个设备的数据，可发送 `unsubscribe` 消息。
8.  **关闭连接**: 在不需要时，主动关闭WebSocket连接。
